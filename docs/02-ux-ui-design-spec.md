# 1. 디자인 방향 정의

## 1.1 이 서비스의 본질

CareerDock은 **보여주는 서비스가 아니라 꺼내 쓰는 서비스**다.

취준생은 불안한 상태에서, 마감에 쫓기며, 하루에도 몇 번씩 이 앱을 연다. 감탄하려고 여는 게 아니라 **자격증 번호를 복사하려고, 마감이 며칠 남았는지 확인하려고** 연다.

그래서 디자인의 목표는 이것이다.

> **화려함이 아니라 "찾는 데 걸리는 시간"을 줄이는 것.**

## 1.2 디자인 원칙 5가지

| 원칙 | 의미 | 실제 적용 |
|---|---|---|
| **1. 불안을 줄인다** | 마감·누락을 놓치지 않게 | 긴급도를 색으로 즉시 구분, 미완료 항목을 숨기지 않음 |
| **2. 밀도는 높이되 답답하지 않게** | 정보량이 많은 서비스 | 여백은 유지, 폰트 크기로 위계 구분 |
| **3. 복사가 쉽다** | 핵심 사용 행동 | 모든 값 옆에 복사 버튼, 클릭 후 즉시 피드백 |
| **4. 지루할 정도로 일관되게** | 매일 쓰는 도구 | 같은 패턴 반복, 화면마다 다른 규칙 금지 |
| **5. 민감정보는 기본적으로 가린다** | 자격번호·개인정보 | 마스킹이 기본값, 눌러야 보임 |

## 1.3 톤 & 무드

```text
차분한   ████████░░  들뜬
신뢰감   █████████░  실험적
따뜻한   ██████░░░░  차가운
밀도높은 ███████░░░  여백많은
```

**한 문장 정의**: 노션의 구조 + 토스의 명료함 + 리니어(Linear)의 절제

# 2. 레퍼런스 사이트 활용 전략

**중요**: 6개 사이트를 똑같은 목적으로 쓰면 안 된다. **랜딩(마케팅) 페이지**와 **제품 내부 화면**은 완전히 다른 디자인 언어를 쓴다.

## 2.1 제품 내부 화면용 (실제 앱 UI)

### ① Refero — **가장 중요. 여기서 80%를 가져온다**
- https://refero.design/
- 실제 출시된 제품의 **대시보드·온보딩·설정·테이블** 화면 12만 장 보유
- Page Type / UX Pattern / UI Element로 검색 가능

**검색할 키워드**:
```text
dashboard        → 대시보드 레이아웃
data table       → 지원 목록 테이블
kanban           → 지원 상태 칸반
file manager     → 내 자료 파일 보관함
tag / filter     → 자소서 라이브러리 필터
detail panel     → 지원건 상세
empty state      → 빈 상태 화면
settings         → 계정·연동 설정
```

### ② Variant / Mobbin 계열 — **패턴 검증용**
- 같은 기능을 다른 서비스는 어떻게 풀었는지 비교
- 특히 **필터 UI**와 **버전 관리 UI**는 직접 설계하지 말고 검증된 패턴을 가져온다

## 2.2 랜딩 페이지 · 비주얼 톤용

### ③ Seesaw — **레이아웃 구성 참고**
- https://www.seesaw.website/
- 벤토(Bento) 그리드 레이아웃이 강점
- **활용**: 대시보드의 카드 배치를 벤토 그리드로 구성할 때 참고

### ④ Land-book — **랜딩 페이지 구조**
- https://land-book.com/
- 20만 개 섹션(Hero/Pricing/Footer)을 개별 검색 가능
- **활용**: 서비스 소개 랜딩 페이지의 Hero·기능소개 섹션 구조

### ⑤ Recent — **최신 트렌드 감각 유지**
- 매일 갱신되는 신규 디자인
- **활용**: 작업 시작 전 10분 훑어보기. 직접 베끼는 용도 아님

### ⑥ Awwwards — **주의해서 쓸 것**
- 화려한 인터랙션·스크롤 애니메이션 중심
- **⚠️ 제품 내부 화면에는 절대 적용하지 말 것.** 매일 쓰는 도구에 무거운 애니메이션은 방해가 된다
- **활용 범위**: 랜딩 페이지의 Hero 영역 **한 곳만**

## 2.3 정리

```text
랜딩 페이지  ← Land-book(70%) + Awwwards(20%) + Seesaw(10%)
제품 내부    ← Refero(80%) + Variant(15%) + Seesaw(5%)
트렌드 감각  ← Recent (매일 10분)
```

# 3. 디자인 시스템 (Figma Foundation 페이지)

## 3.1 컬러

### Primary — 신뢰
```text
primary-50    #EEF2FF
primary-100   #E0E7FF
primary-500   #4F5BD5   ← 메인 (버튼, 링크, 활성 상태)
primary-600   #3F49B8   ← hover
primary-700   #333C99   ← pressed
```
> 파랑 계열을 쓰되 **은행 파랑(#0066CC)은 피한다.** 너무 딱딱하고 흔하다. 살짝 보라가 섞인 인디고가 도구다운 인상을 준다.

### Neutral — 따뜻한 회색 (차가운 회색 금지)
```text
neutral-0     #FFFFFF   배경
neutral-50    #FAFAF9   페이지 배경
neutral-100   #F5F5F4   카드 구분 배경
neutral-200   #E7E5E4   보더
neutral-400   #A8A29E   비활성 텍스트
neutral-600   #57534E   보조 텍스트
neutral-900   #1C1917   본문 텍스트
```
> 순수 회색(#808080)이 아닌 **따뜻한 회색(stone 계열)**을 쓴다. 취준이라는 불안한 맥락에서 차가운 회색은 병원 같은 인상을 준다.

### Semantic — 마감 긴급도 (**이 서비스의 핵심**)
```text
urgent-red     #DC2626   D-1 이하   "오늘/내일 마감"
urgent-orange  #EA580C   D-2 ~ D-3  "곧 마감"
urgent-amber   #D97706   D-4 ~ D-7  "이번 주"
calm-blue      #2563EB   D-8 이상   "여유"
neutral-400    #A8A29E   마감 지남   "종료"
```

### Status — 지원 전형 단계 7종
```text
관심      neutral-400  회색
작성 중    amber-500    노랑
지원 완료  blue-500     파랑
서류 결과  indigo-500   남색
필기/코테  violet-500   보라
면접      fuchsia-500  자홍
최종 합격  emerald-500  초록
최종 불합격 neutral-300  연회색 (+ 취소선 아님, 투명도 60%)
```
> 왼쪽에서 오른쪽으로 갈수록 **채도가 올라간다.** 전형이 진행될수록 색이 진해져 시각적으로 "진전"을 느끼게 한다.

### 접근성
- 본문 텍스트 대비 **4.5:1 이상** 필수
- **색만으로 정보를 전달하지 않는다.** 긴급도는 색 + `D-3` 텍스트를 함께 표기

## 3.2 타이포그래피

**폰트**: `Pretendard` (한글 필수. Noto Sans KR보다 자간이 좁아 밀도 높은 UI에 유리)

```text
display   32px / 700 / -0.02em    페이지 대제목
h1        24px / 700 / -0.02em    화면 제목
h2        20px / 600 / -0.01em    섹션 제목
h3        16px / 600 / 0          카드 제목
body      14px / 400 / 0          본문 (기본)
body-md   14px / 500 / 0          강조 본문
caption   12px / 400 / 0          보조 설명, 라벨
mono      13px / 400              자격번호, 날짜, 글자수
```

**규칙**
- 기본 본문은 **14px**. 정보 밀도가 높은 도구형 서비스는 16px이면 너무 크다
- 자격번호·날짜·글자수는 **고정폭(mono)** 폰트 → 숫자 정렬이 맞고 복사할 값처럼 보인다
- 줄간격: 본문 1.6, 제목 1.3

## 3.3 간격 (4px 배수)

```text
4  8  12  16  20  24  32  40  48  64
```
- 컴포넌트 내부 패딩: 12 / 16
- 카드 간 간격: 16
- 섹션 간 간격: 32
- 페이지 좌우 여백: 24 (모바일) / 40 (데스크톱)

## 3.4 모서리 · 그림자

```text
radius-sm   6px    뱃지, 태그
radius-md   10px   버튼, 인풋
radius-lg   14px   카드
radius-xl   20px   모달
```

```text
shadow-sm   0 1px 2px rgba(28,25,23,0.05)      카드 기본
shadow-md   0 4px 12px rgba(28,25,23,0.08)     드롭다운, 팝오버
shadow-lg   0 12px 32px rgba(28,25,23,0.12)    모달
```
> **그림자는 최소한으로.** 카드 구분은 그림자보다 **보더(neutral-200)**를 우선 사용한다. 그림자를 남발하면 화면이 지저분해진다.

# 4. 컴포넌트 목록 (Figma 컴포넌트로 제작)

## 우선순위 1 — 없으면 화면을 못 만듦
- [ ] **Button** — primary / secondary / ghost / danger × sm·md·lg × default·hover·pressed·disabled·loading
- [ ] **Input** — text / textarea / date / select × default·focus·error·disabled
- [ ] **Badge** — 전형 상태 7종, 긴급도 5종
- [ ] **Card** — 기본 / 클릭가능 / 강조
- [ ] **Sidebar Nav Item** — default·hover·active
- [ ] **Page Header** — 제목 + 설명 + 우측 액션 버튼

## 우선순위 2 — 핵심 기능
- [ ] **D-day Chip** — `D-3` 형태, 긴급도 색 자동 반영
- [ ] **Copy Field** — 값 + 복사 버튼 + 복사 완료 피드백
- [ ] **Masked Field** — 자격번호용. 마스킹 상태 / 공개 상태
- [ ] **Progress Bar** — 지원서 완성도(%)
- [ ] **Checklist Item** — 체크박스 + 텍스트 + 완료 취소선
- [ ] **File Chip** — 파일명 + 확장자 아이콘 + 보기/다운로드
- [ ] **Filter Chip** — 선택 가능한 태그, 다중 선택
- [ ] **Empty State** — 아이콘 + 안내 문구 + 액션 버튼

## 우선순위 3 — 마감 품질
- [ ] **Modal** / **Toast** / **Tooltip** / **Dropdown**
- [ ] **Tab** / **Table Row** / **Skeleton Loader**
- [ ] **Version Item** — 자소서·파일 버전 목록용

# 6. 화면별 상세 기획

## 6.1 대시보드 — **10초 안에 오늘 할 일 파악**

```text
┌────────────────────────────────────────────────────────┐
│  안녕하세요, 예준님 👋                                    │
│  이번 주 마감 3건, 다가오는 일정 2건이 있어요               │
├────────────────────────────────────────────────────────┤
│                                                        │
│  ⚠️ 임박한 마감                              [전체보기]   │
│  ┌──────────────────┐ ┌──────────────────┐            │
│  │ D-2  🔴          │ │ D-6  🟡          │            │
│  │ KB국민은행         │ │ 신한은행          │            │
│  │ IT 개발           │ │ ICT             │            │
│  │ ▓▓▓▓▓▓▓░░░ 78%  │ │ ▓▓░░░░░░░░ 20%  │            │
│  │ 미완료: 자소서 2문항│ │ 미완료: 기본정보   │            │
│  └──────────────────┘ └──────────────────┘            │
│                                                        │
├────────────────────────────────────────────────────────┤
│  📅 다가오는 일정        │  ⏰ 만료 예정 서류              │
│  ┌────────────────────┐│  ┌───────────────────────┐   │
│  │ 8/12 코딩테스트     ││  │ 토익  D-24 만료        │   │
│  │ 카카오             ││  │ 성적증명서 D-11 만료    │   │
│  │                   ││  │                       │   │
│  │ 8/18 1차 면접      ││  └───────────────────────┘   │
│  │ 네이버             ││  📄 최근 연 자소서            │
│  └────────────────────┘│  ┌───────────────────────┐   │
│                        │  │ KB · 지원동기          │   │
│                        │  │ 신한 · 문제해결        │   │
│                        │  └───────────────────────┘   │
└────────────────────────────────────────────────────────┘
```

**설계 의도**
- 최상단은 **불안 해소 영역**. 마감이 임박한 것만 크게, 나머지는 아래로
- 진행률 바 옆에 **"미완료: 자소서 2문항"** 처럼 다음 행동을 명시 → 클릭하면 바로 그 화면으로
- 카드 배치는 **Seesaw의 벤토 그리드** 참고
- 마감 없으면 "이번 주는 여유롭네요" 같은 **빈 상태**를 제대로 디자인 (불안 유발 금지)

## 6.2 지원 관리 — 목록 / 칸반 전환

```text
┌────────────────────────────────────────────────────────┐
│  지원 관리                        [목록|칸반]  [+ 등록]  │
│  [전체 12] [작성중 3] [지원완료 5] [면접 2]              │
│  🔍 검색                        [연도▾] [상태▾] [정렬▾] │
├────────────────────────────────────────────────────────┤
│  회사        직무      마감      상태      완성도        │
│ ─────────────────────────────────────────────────────  │
│  KB국민은행   IT개발   D-2 🔴   작성중   ▓▓▓▓▓▓▓░ 78%  │
│  신한은행     ICT     D-6 🟡   작성중   ▓▓░░░░░░ 20%  │
│  카카오       백엔드   지원완료  코테     ▓▓▓▓▓▓▓▓100%  │
└────────────────────────────────────────────────────────┘
```

**칸반 뷰**: 전형 상태 7개를 컬럼으로. 드래그로 상태 변경 → 변경 시 이력 자동 기록

**설계 의도**
- 목록이 기본. 칸반은 전체 흐름을 볼 때
- **정렬 기본값 = 마감 임박순.** 사용자가 가장 자주 원하는 순서
- Refero에서 `data table`, `kanban` 검색해 패턴 참고

## 6.3 지원 상세 — **한 지원건의 모든 것**

```text
┌────────────────────────────────────────────────────────┐
│  ← 지원 관리                                            │
│  KB국민은행 · IT 개발                        [수정] [⋯] │
│  2026 하반기 · 마감 2026.09.14 18:00 · D-2 🔴          │
│  [작성 중 ▾]  ← 클릭 시 상태 변경                        │
├────────────────────────────────────────────────────────┤
│  [개요] [자소서] [제출자료] [일정] [체크리스트] [이력]     │
├────────────────────────────────────────────────────────┤
│  완성도 ▓▓▓▓▓▓▓░░ 78%                                  │
│  ✅ 기본정보  ✅ 자소서  ⬜ 파일연결  ⬜ 최종검토         │
│                                                        │
│  공고 링크  🔗 recruit.kbstar.com/...        [열기]     │
│  근무지역   서울 여의도                                  │
│  메모       NCS 필기 있음. 코테 없음                     │
└────────────────────────────────────────────────────────┘
```

**설계 의도**
- 탭으로 나누되 **완성도와 체크리스트는 항상 상단에 고정** → 무엇이 남았는지 계속 보이게
- 상태 변경은 상세 화면에서 바로. 이력은 자동 기록

## 6.4 자소서 라이브러리 — **차별점이 드러나는 화면**

```text
┌────────────────────────────────────────────────────────┐
│  자소서 라이브러리                          [+ 문항 추가] │
│                                                        │
│  보기: [공통유형] [회사별] [직무별] [경험소재별]           │
│                                                        │
│  공통유형  [지원동기 8] [성장과정 5] [문제해결 6] [협업 4] │
│  경험소재  [LOODI 7] [온세미컨덕터 3] [기사단 2]          │
│  상태     [작성본] [제출본] [개선본]                     │
│  ─────────────────────────────────────────────────     │
│  선택된 필터: 지원동기 ✕  LOODI ✕  제출본 ✕   [초기화]   │
├────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────┐ │
│  │ 🔒 제출본 · 2026.09.14 제출                        │ │
│  │ KB국민은행 · IT 개발 · 문항 1                       │ │
│  │ "우리 은행에 지원한 이유를 작성하세요" (800자)        │ │
│  │                                                  │ │
│  │ 저는 데이터 기반 문제 해결에 관심을 두고 LOODI...    │ │
│  │                                        [768자]   │ │
│  │ 🏷 지원동기  LOODI  문제해결                       │ │
│  │                    [전체 복사] [새 지원서로 복제]    │ │
│  └──────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```

**설계 의도 — 가장 공들일 화면**
- **다중 필터가 핵심 가치.** `은행 IT + 문제해결 + LOODI + 제출본` 조합이 즉시 되어야 함
- 선택된 필터를 **칩으로 상단에 노출**하고 개별 삭제 가능 (Refero의 filter 패턴)
- **제출본은 자물쇠 아이콘 + 배경색 구분.** 수정 불가임을 시각적으로 명확히
- 카드에서 바로 **[전체 복사]** — 이 서비스에서 가장 많이 눌릴 버튼
- 본문은 3줄로 자르고 클릭 시 펼침

## 6.5 내 자료 — 자격증 상세

```text
┌────────────────────────────────────────────────────────┐
│  SQLD · SQL 개발자                          [수정] [⋯] │
│  🏷 국가공인   ✅ 영구 자격                              │
├────────────────────────────────────────────────────────┤
│  취득일      2025.06.27                    [복사]      │
│  자격번호     SQLD-12••••••          [👁 표시] [복사]   │
│  발급기관     한국데이터산업진흥원            [복사]      │
│  유효기간     영구                                      │
│  증빙파일     📄 SQLD_송주영.pdf      [보기] [다운로드]  │
├────────────────────────────────────────────────────────┤
│  자격 설명                                              │
│  데이터 모델링, SQL 기본 및 활용 역량을 검증하는 자격       │
│                                                        │
│  내 활용 메모                                           │
│  · 은행 IT 지원서 자격사항에 기재                         │
│  · 데이터베이스 직무역량 근거로 활용                       │

│  공부 내용 (면접용)                                      │
│  · 정규화와 반정규화 트레이드오프를 실제로 경험            │
├────────────────────────────────────────────────────────┤
│  사용 이력                                              │
│  KB국민은행 IT개발 · 신한은행 ICT                        │
└────────────────────────────────────────────────────────┘
```

**설계 의도**
- **모든 값에 복사 버튼.** 이 화면의 존재 이유
- 자격번호는 **기본 마스킹**, `👁` 눌러야 공개 (스펙 5.5-B 요구사항)
- 설명을 3영역(자격설명 / 활용메모 / 공부내용)으로 분리 → 면접 직전에 열어보는 용도
- **사용 이력**으로 "이 자격증을 어디에 썼는지" 역추적

## 6.6 캘린더

```text
┌────────────────────────────────────────────────────────┐
│  캘린더            [월|주]  ◀ 2026년 9월 ▶   [+ 일정]   │
├────────────────────────────────────────────────────────┤
│  일   월   화   수   목   금   토                        │
│           1    2    3    4    5                        │
│                    ┃마감                                │
│  6    7    8    9   10   11   12                       │
│            ┃코테           ┃면접                        │
├────────────────────────────────────────────────────────┤
│  다가오는 일정                                          │
│  9/14(월) 18:00  KB국민은행 지원마감      D-2 🔴        │
```

**설계 의도**

- 하단 **다가오는 일정 리스트가 실질적으로 더 많이 쓰임** → 캘린더와 동등한 비중
- 2주차에 시간 부족하면 **캘린더 격자를 버리고 리스트만** 남겨도 기능은 성립

# 7. 빈 상태 (Empty State) — 반드시 디자인할 것

신규 사용자는 **모든 화면이 비어 있는 상태**로 시작한다. 이걸 디자인 안 하면 첫인상이 망가진다.

| 화면 | 문구 | 액션 |
|---|---|---|
| 대시보드 | "아직 등록된 지원건이 없어요" | [첫 지원건 등록하기] |
| 지원 관리 | "지원할 회사를 등록해보세요" | [+ 지원건 등록] |
| 자소서 | "저장된 자소서가 없어요<br>지원건을 만들면 문항을 추가할 수 있어요" | [지원건 만들기] |
| 내 자료 | "자격증을 등록하면 지원서 쓸 때 바로 꺼내 쓸 수 있어요" | [+ 자격증 등록] |
| 필터 결과 없음 | "조건에 맞는 자소서가 없어요" | [필터 초기화] |

> **금지**: "데이터가 없습니다" 같은 무미건조한 문구. 다음에 뭘 해야 할지 알려줘야 한다.

# 8. 반응형

```text
Desktop   1280px+   사이드바 고정 + 2~3열 그리드
Laptop    1024px    사이드바 고정 + 2열
Tablet    768px     사이드바 접힘(아이콘) + 1열
Mobile    375px     하단 탭바 + 1열
```

**모바일 우선순위**: 대시보드 확인 / 자소서 복사 / 자격증 번호 복사
→ **작성·편집은 데스크톱 전제.** 모바일은 "조회와 복사"에 집중한다.

# 9. 접근성 체크리스트

- [ ] 본문 대비 4.5:1, 큰 텍스트 3:1 이상
- [ ] 색만으로 상태 구분 금지 (색 + 텍스트/아이콘 병행)
- [ ] 모든 인터랙션 요소 키보드 접근 가능, focus ring 명확히
- [ ] 터치 타깃 최소 44×44px
- [ ] 폼 에러는 **입력 필드 바로 아래** 텍스트로 (색만으로 표시 금지)
- [ ] 아이콘 단독 버튼에 aria-label

# 10. Figma 파일 구조

```text
CareerDock Design
├── 📄 00 · Cover
├── 📄 01 · Foundation      컬러 / 타이포 / 간격 / 아이콘
├── 📄 02 · Components      컴포넌트 라이브러리 (Variants 필수)
├── 📄 03 · Wireframe       저해상도 구조 설계
├── 📄 04 · Design          최종 화면
│   ├── Auth
│   ├── Dashboard
│   ├── Applications
│   ├── Essays
│   ├── Credentials
│   └── Calendar
├── 📄 05 · Responsive      태블릿 / 모바일
└── 📄 06 · Handoff         개발 전달용 (스펙 주석)
```

**규칙**
- 컬러·텍스트는 **반드시 Variables/Styles로 등록.** 하드코딩 금지 → 개발자가 토큰으로 그대로 옮김
- 컴포넌트는 **Variants**로 상태 관리 (`Button/primary/md/hover`)
- 네이밍은 **개발 코드와 동일하게** (`btn-primary`, `badge-urgent`)
- Auto Layout 필수 → 반응형 대응이 쉬워짐

# 11. 작업 순서 (2주 계획과 연동)

| 날짜 | 작업 | 완료 기준 |
|---|---|---|
| 8/3(월) | Foundation + 우선순위1 컴포넌트 | 송주영이 컬러 토큰 코드화 가능 |
| 8/4(화) | 와이어프레임 6화면 | 구조 확정, 스타일 없음 |
| 8/5(수) | 대시보드 + 지원관리 디자인 | 픽셀 단위 완성 |
| 8/6(목) | 자소서 + 내 자료 디자인 | 픽셀 단위 완성 |
