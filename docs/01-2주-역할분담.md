## 1. 역할 정의

| 담당 | 이름 | 역할 |
|---|---|---|
| A | 권예준 | 기획 · 디자인 · API 설계 · 백엔드 |
| B | 송주영 | 프론트엔드 구현 (Next.js + TypeScript) |

### 권예준 (A)
- Figma UX/UI 디자인 (→ `02-ux-ui-design-spec.md`)
- 제안서 작성
- API 명세 확정 및 백엔드(Spring Boot) 구현
- **B가 프론트 작업을 시작할 수 있도록 디자인과 API 명세를 항상 앞서서 공급**

### 송주영 (B)
- Next.js 화면 구현
- API 연동
- 컴포넌트 · 디자인 시스템 코드화

### 협업 원칙
> **A는 항상 B보다 최소 2~3일 앞서 산출물을 낸다.**

B가 대기하지 않게 하는 것이 A의 핵심 책임이다. 그래서 A는 1주차 초반에 **디자인과 API 명세를 몰아서** 끝낸다.

## 2. 선행 의존성 (가장 중요)

```text
A: 디자인 + API 명세  ──2~3일 선행──▶  B: 화면 구현
A: 백엔드 API 구현    ──병렬────────▶  B: 목데이터로 UI 먼저
```

- B는 API가 없어도 **목(Mock) 데이터로 UI를 먼저 만든다.** 백엔드 대기 금지.
- A는 API 명세(요청/응답 JSON 예시)를 **코드보다 먼저** 확정해 B에게 준다.
- 명세만 있으면 B는 목 데이터를 명세대로 만들고, 나중에 URL만 바꿔 끼우면 된다.

## 6. 브랜치 전략

```text
main                  ← 배포 가능한 상태만
├── feature/auth      ← A
├── feature/api-*     ← A
├── feature/ui-*      ← B
└── feature/screen-*  ← B
```

- 각자 `feature/` 브랜치에서 작업 → push → PR 생성
- **main 직접 push 금지**
- PR은 상대방이 확인 후 merge
- 하루 최소 1회 push (작업 상황 공유)
