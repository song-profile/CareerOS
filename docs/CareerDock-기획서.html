CareerDock UX/UI 디자인 기획서 v1.0

작성 기준: 2026.08.01 · Figma 작업용 · 담당 권예준

1. 디자인 방향 정의

1.1 이 서비스의 본질

CareerDock은 보여주는 서비스가 아니라 꺼내 쓰는 서비스다.

취준생은 불안한 상태에서, 마감에 쫓기며, 하루에도 몇 번씩 이 앱을 연다. 감탄하려고 여는 게 아니라 자격증 번호를 복사하려고, 마감이 며칠 남았는지 확인하려고 연다.

그래서 디자인의 목표는 이것이다.

화려함이 아니라 "찾는 데 걸리는 시간"을 줄이는 것.

1.2 디자인 원칙 5가지

원칙 의미 실제 적용
1. 불안을 줄인다 마감·누락을 놓치지 않게 긴급도를 색으로 즉시 구분, 미완료 항목을 숨기지 않음
2. 밀도는 높이되 답답하지 않게 정보량이 많은 서비스 여백은 유지, 폰트 크기로 위계 구분
3. 복사가 쉽다 핵심 사용 행동 모든 값 옆에 복사 버튼, 클릭 후 즉시 피드백
4. 지루할 정도로 일관되게 매일 쓰는 도구 같은 패턴 반복, 화면마다 다른 규칙 금지
5. 민감정보는 기본적으로 가린다 자격번호·개인정보 마스킹이 기본값, 눌러야 보임

2. 레퍼런스 사이트 활용 전략

중요: 6개 사이트를 똑같은 목적으로 쓰면 안 된다. 랜딩(마케팅) 페이지와 제품 내부 화면은 완전히 다른 디자인 언어를 쓴다.

2.1 제품 내부 화면용 (실제 앱 UI)

① Refero — 가장 중요. 여기서 80%를 가져온다

  • https://refero.design/
  • 실제 출시된 제품의 대시보드·온보딩·설정·테이블 화면 12만 장 보유
  • Page Type / UX Pattern / UI Element로 검색 가능

검색할 키워드:

dashboard        → 대시보드 레이아웃
data table       → 지원 목록 테이블
kanban           → 지원 상태 칸반
file manager     → 내 자료 파일 보관함
tag / filter     → 자소서 라이브러리 필터
detail panel     → 지원건 상세
empty state      → 빈 상태 화면
settings         → 계정·연동 설정

② Variant / Mobbin 계열 — 패턴 검증용

  • 같은 기능을 다른 서비스는 어떻게 풀었는지 비교
  • 특히 필터 UI와 버전 관리 UI는 직접 설계하지 말고 검증된 패턴을 가져온다

2.2 랜딩 페이지 · 비주얼 톤용

③ Seesaw — 레이아웃 구성 참고

  • https://www.seesaw.website/
  • 벤토(Bento) 그리드 레이아웃이 강점
  • 활용: 대시보드의 카드 배치를 벤토 그리드로 구성할 때 참고

④ Land-book — 랜딩 페이지 구조

  • https://land-book.com/
  • 20만 개 섹션(Hero/Pricing/Footer)을 개별 검색 가능
  • 활용: 서비스 소개 랜딩 페이지의 Hero·기능소개 섹션 구조

⑤ Recent — 최신 트렌드 감각 유지

  • 매일 갱신되는 신규 디자인
  • 활용: 작업 시작 전 10분 훑어보기. 직접 베끼는 용도 아님

⑥ Awwwards — 주의해서 쓸 것

  • 화려한 인터랙션·스크롤 애니메이션 중심
  • ⚠️ 제품 내부 화면에는 절대 적용하지 말 것. 매일 쓰는 도구에 무거운 애니메이션은 방해가 된다
  • 활용 범위: 랜딩 페이지의 Hero 영역 한 곳만

2.3 정리

랜딩 페이지  ← Land-book(70%) + Awwwards(20%) + Seesaw(10%)
제품 내부    ← Refero(80%) + Variant(15%) + Seesaw(5%)
트렌드 감각  ← Recent (매일 10분)

3.2 타이포그래피

폰트: Pretendard (한글 필수. Noto Sans KR보다 자간이 좁아 밀도 높은 UI에 유리)

display   32px / 700 / -0.02em    페이지 대제목
h1        24px / 700 / -0.02em    화면 제목
h2        20px / 600 / -0.01em    섹션 제목
h3        16px / 600 / 0          카드 제목
body      14px / 400 / 0          본문 (기본)
body-md   14px / 500 / 0          강조 본문
caption   12px / 400 / 0          보조 설명, 라벨
mono      13px / 400              자격번호, 날짜, 글자수

규칙

  • 기본 본문은 14px. 정보 밀도가 높은 도구형 서비스는 16px이면 너무 크다
  • 자격번호·날짜·글자수는 고정폭(mono) 폰트 → 숫자 정렬이 맞고 복사할 값처럼 보인다
  • 줄간격: 본문 1.6, 제목 1.3

  • 카드 간 간격: 16
  • 섹션 간 간격: 32
  • 페이지 좌우 여백: 24 (모바일) / 40 (데스크톱)

  • Masked Field — 자격번호용. 마스킹 상태 / 공개 상태

  • Empty State — 아이콘 + 안내 문구 + 액션 버튼

우선순위 3 — 마감 품질

  • Modal / Toast / Tooltip / Dropdown
  • Tab / Table Row / Skeleton Loader
  • Version Item — 자소서·파일 버전 목록용

7. 빈 상태 (Empty State) — 반드시 디자인할 것

신규 사용자는 모든 화면이 비어 있는 상태로 시작한다. 이걸 디자인 안 하면 첫인상이 망가진다.

화면 문구 액션
대시보드 "아직 등록된 지원건이 없어요" [첫 지원건 등록하기]
지원 관리 "지원할 회사를 등록해보세요" [+ 지원건 등록]
자소서 "저장된 자소서가 없어요
지원건을 만들면 문항을 추가할 수 있어요"		 [지원건 만들기]
내 자료 "자격증을 등록하면 지원서 쓸 때 바로 꺼내 쓸 수 있어요" [+ 자격증 등록]
필터 결과 없음 "조건에 맞는 자소서가 없어요" [필터 초기화]

금지: "데이터가 없습니다" 같은 무미건조한 문구. 다음에 뭘 해야 할지 알려줘야 한다.

8. 반응형

Desktop   1280px+   사이드바 고정 + 2~3열 그리드
Laptop    1024px    사이드바 고정 + 2열
Tablet    768px     사이드바 접힘(아이콘) + 1열
Mobile    375px     하단 탭바 + 1열

모바일 우선순위: 대시보드 확인 / 자소서 복사 / 자격증 번호 복사 → 작성·편집은 데스크톱 전제. 모바일은 "조회와 복사"에 집중한다.

9. 접근성 체크리스트

  • 본문 대비 4.5:1, 큰 텍스트 3:1 이상
  • 색만으로 상태 구분 금지 (색 + 텍스트/아이콘 병행)
  • 모든 인터랙션 요소 키보드 접근 가능, focus ring 명확히
  • 터치 타깃 최소 44×44px
  • 폼 에러는 입력 필드 바로 아래 텍스트로 (색만으로 표시 금지)
  • 아이콘 단독 버튼에 aria-label

8/6(목) 자소서 + 내 자료 디자인 픽셀 단위 완성
8/7(금) 빈 상태 + 로그인 화면 전체 화면 커버
8/10(월) 반응형 + Handoff 정리 개발 착수 가능

8/4(화) 와이어프레임이 나오는 즉시 송주영에게 공유한다. 완성 디자인을 기다리게 하지 말 것. 구조만 있어도 레이아웃 코딩은 시작할 수 있다.

12. 이번 버전에서 하지 않는 것

의도적으로 뺀다. 시간이 남으면 그때 한다.

  • 다크 모드 (2주 안에는 무리, 라이트만)
  • 페이지 전환 애니메이션 (기본 페이드만)
  • 커스텀 일러스트 (빈 상태는 아이콘 + 텍스트로)
  • 온보딩 투어
  • 스크롤 인터랙션 (Awwwards식 연출은 랜딩에서만)
